# Приоритет входящих заявок

Демонстрационный сервис **tagiltsev_ml**.

Задача заказчика: из таблицы входящих обращений получить список, с кем работать в первую очередь.

Это открытое демо, не внедрение в компании-клиенте. Модель обучена на учебной выборке в репозитории. На чужих данных качество будет другим.

## Что на выходе

- оценка вероятности целевого действия (`priority_score`);
- группа: низкий / средний / высокий;
- CSV, отсортированный по убыванию приоритета.

## Как запустить локально

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python src/train.py
streamlit run app.py
```

Откроется страница: загрузка CSV или учебный пример.

## Какие колонки нужны

`source`, `device`, `city`, `pages_viewed`, `session_minutes`, `repeat_visit`, `form_filled`

Необязательные поля сохраняются в выгрузке, если они есть во входе.

Учебный пример: `data/sample_leads.csv`. Целевая колонка `target_deal` используется только при обучении.

## Как устроено

1. Категории кодируются, числа идут как есть.
2. Обучается градиентный бустинг на таблицах.
3. На отложенной части учебной выборки считается ROC-AUC.
4. Приложение применяет сохранённую модель и не переобучается на файле заказчика.

Для пилота у клиента обычно достаточно такого же цикла на его разметке.

## Ограничения

- без колонки результата на стороне клиента модель нельзя честно переобучить под его процесс;
- учебные заявки не равны вашему потоку;
- сервис не обещает рост конверсии, только порядок разбора.
